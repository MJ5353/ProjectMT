# 26.11.18 - 데이터 도구·전투 구현·리소스 제작

## 주요 작업

- 데이터 편집·자동 배정, 부위 파괴·공격·스폰 구현을 AI에 맡기고 직접 구조와 전투 범위를 정함.
- 직접 용도·컨셉을 정해 지역·버섯·시장·HUD 아이콘 제작을 AI에 맡김.

## 데이터 편집기와 자동 배정

- 필드 나열식 초안을 거절하고 타입별 표 편집·연관 데이터·모델 차이·빌드를 요구. AI가 UI Toolkit 편집기로 구현하고 임시 에셋으로 값·GUID·저장·Undo 보존을 확인함.
- 맵·버섯·몬스터 연계와 순서 기반 밸런스·스폰 배정을 직접 요청. 판정·히트스톱은 자동 배정에서 제외하고, 공유 HitDef를 보호하려 넉백 자동 배정도 제거함.

## 피격과 부위 파괴

- 직접 피격 반응 통합과 보스 나무 기준·보스만 부위 파괴하는 범위를 정하고 수치는 손으로 이전. AI가 HitFeature·공유 HitDef·뼈 기반 판정을 구현함.
- 직접 부위 단위 파괴·랜덤 버섯 배치를 선택해 PartEntry·UnitProperty와 유닛당 PartFeature 하나로 정리. 모델은 미리 만들어 재배치하고, 잡몹 소켓은 장식 부위로 보존함.
- 깨지지 않는 부위의 번쩍 오류를 수정하고, 통 메시의 부위별 번쩍 대신 피격 위치의 도트 마크를 채택. 보스 부위·드롭·공격 값은 가안으로 연결함.

## 공격과 애니메이션

- 공격 구간·공용/개별 쿨·기본 공격의 SkillDef화를 직접 결정. AI가 요청받은 공격 애니를 제작하고 콤보·달리다 베기·위로 치기·길게 누르기 회오리를 연결함.
- 입력 지연을 피하려 즉시 콤보 후 회오리를 잇도록 정하고, 회오리 재타격과 보스 공격 거리 오류를 수정. 컴파일·로드 확인 기록을 남김.

## 스폰과 실행 구조

- 슬롯별 MonsterDef 직접 참조와 맵 프리팹 생성을 채택. 낙하 원인인 슬롯 회전을 임포터에서 고치고, 올라타기 원인인 자동 계단 오르기와 바닥 스냅을 정리해 수동 이동으로 해소함.
- 지형이 물리 쿼리 버퍼를 채우는 문제를 피하려 레이어·맵 래핑·직접 거리 비교를 선택. 실행·콤보는 공용화하고 유닛 갱신·삭제를 서비스에 모았으며 씬 직접 배치는 제외함.

## 리소스·보조 작업

- AI가 지역 3종과 버섯·시장·HUD 아이콘을 제작.
- 직접 콘텐츠 번호·이름과 세이브 초기화를 결정하고, AI가 GUID·직렬화를 보존해 이전. 사전 Inspector·메뉴·문서·개발 환경을 정리하고 불필요한 graphify 연결을 제거함.

# 26.11.19 - 유닛 구조·전투 연출·HUD 정리

## 주요 작업

- 유닛을 부품·실행기·판단으로 나누고, 전투 연출·HUD·입력·카메라를 정리.
- 직접 플레이와 검토로 AI의 구조·효과 제안을 교정하고 제출 범위·라이선스를 결정.

## 유닛 책임과 데이터

- Feature에 판단·상태·능력이 섞인 문제를 직접 지적. AI의 중간 분리안을 거쳐 부품·실행기·판단 세 층과 단방향 호출을 채택하고, 부품·실행기·판단 분리 때 직접 컴파일을 확인함.
- 종류별 판단 상속이 늘어나는 안을 거절하고 AIBrain·공통 상태·공유 AIDef 프리셋으로 정리하도록 지시. 컨트롤러는 하나로 합치고 조립·팀·판단 차이는 Def가 정하게 함.
- Def를 스폰 때 넘기고 프리팹은 ID로 조회하도록 직접 결정해 순환 참조를 제거. 프리팹 뼈 참조와 GUID는 보존함.
- 펫은 플레이어 편·무적·타깃 제외·보상 제외로 지정. 보스 공격이 피격에 끊기는 문제는 경직 누적값과 다운·포효 중 경직 금지로 수정함.
- 숨은 적의 조준 제외는 IsHidden으로 구분. AI가 무적 전체를 제외하면 피격 직후 콤보 조준이 튄다고 짚어 숨기 전용으로 좁힘.

## 전투 연출

- 공격·부위 파괴·사망·줍기 효과를 EffectService와 기존 풀로 모으도록 지시. AI가 파티클·조각·타격 마크를 연결했으며 연출 수치는 가안으로 둠.
- 카메라는 공격 세기에 따라 앞으로 다가왔다 복귀하는 방식으로 직접 결정. 충격파 고리는 플레이 후 스킬 효과와 겹쳐 조잡하다고 판단해 제거하고, 공격 범위를 읽는 바닥 예고로 방향을 바꿈.
- 원형 공격과 돌진 경로 예고를 함께 구현하도록 선택. 당시 가이드는 시작 돌진·판정 뼈 자세 차이를 반영하지 않았으며, 가림 실루엣은 URP Render Objects 방식을 채택함.

## 전투 규칙과 HUD

- 직접 토벌 종료·시간 초과·사망 보상을 구분하고, 사망은 골드 부활/귀가 선택과 버섯을 떨구는 연출로 정함. AI가 HUD·사망 팝업·부활·밤 시계를 구현하고 컴파일 통과를 기록함.
- 체력바·보스 포효·현재 공격과 연계 스킬 표시를 추가. 직접 손본 프리팹을 보존하며 생성기에 반영하고, 임포트 방식 변경으로 끊긴 스킬 아이콘 참조를 수정함.
- 용도·컨셉은 직접 정하고 AI가 스킬 아이콘·밤 시계·지도 배경·지역 표시를 제작·연결.

## 전역 설정과 보스 데이터

- 플레이어와 무관한 조절값은 DefineDef로, 에디터 경로는 EditorPath로 옮기도록 선택. CommonPath는 공용 경로를 맡기고 로컬 상수·이펙트 Def화는 보류함.
- 중복된 AI 밸런스 칸을 제거하고 보스별 분노 스킬은 MonsterDef로 이동. 대표기를 분노 뒤로 미룬 초안은 전용 애니 제작 후 되돌리고, 보스별 Skill_04를 분노 전용으로 연결함.

## 입력·카메라·문서·제출

- 입력 생성 클래스와 관리 위치는 직접 준비하고, AI가 InputManager·CameraManager·씬 컨트롤러 분리를 구현함.
- 11/20 제출을 앞두고 AI에 범위 평가를 맡김. 당시 부족했던 시장·밤 시간·정비를 우선하고 개량·파견은 준비 중으로 줄이는 안을 제안받음.
- 직접 자체 결과물 보호를 선택해 열람·심사용 All Rights Reserved LICENSE를 작성하고 Galmuri의 OFL은 예외로 둠.
- 진행은 Goals, 과거 기록은 Records로 분리하고 루트 지침은 작업 규칙을 참조하게 정리. AI 로그는 날짜·주제별로 맡긴 일·직접 판단·결과를 남기도록 정함.

# 26.11.20 - 시장 구현과 UI 공용 구조

## 주요 작업

- 시장 데이터·거래·UI와 공용 목록·팝업·문구·생성 도구를 구현.
- 직접 데이터 소유권·재사용·명명 원칙을 정하고 AI의 불필요한 분리안을 교정.

## 시장 규칙과 데이터

- 별도 MarketService·MarketRule 초안을 거절. 시장은 결정할 때만 시간이 흐르고 이후 서버로 옮길 부분이라 HuntData가 상태·판정을, UI는 요청만 맡도록 정함.
- 거래 상한을 5개에서 같은 버섯·희귀도·신선도의 5묶음으로 변경. 기다리기는 상인 재추첨 대신 시세 변동으로 정하고 경쟁·담합·시간대·주문은 최소판에서 제외함.
- 희귀도는 버섯 고정값이나 줍는 순간이 아니라 드롭 때 지역 가중치로 결정하도록 지시. AI가 공용 확률 유틸과 시장·신뢰도 저장을 연결함.

## 시장·로비 표시와 리소스

- 직접 스케치와 조작을 정해 AI가 시장 팝업·시간 환산·묶음 선택·개수 조절·로비 툴팁을 구현. 슬롯은 희귀도와 신선도를 구분해 표시하고 중복 뱃지는 제거함.
- AI에 시장 슬롯 그림을 제작하도록 맡김. 희귀도 효과는 시인성·완성도 문제로 거절한 뒤 기존 EffectController의 빛기둥만 다시 채택했으며, AI의 결과물 미확인 보고·옛 사본 전달 오류도 있었음.

## 목록·팝업 재사용

- 직접 화면은 데이터를, 칸은 표시를 맡도록 정하고 AI가 목록·칸을 Resources 프리팹과 공용 풀로 이전. UIListView는 배치까지 담당하고, 별도 배치 컴포넌트는 불필요해 거절함.
- UI 요소는 재활용 서비스가 회수하고 팝업은 종류당 하나를 재사용하도록 채택. 씬 전환 시 팝업보다 내부 UI 요소를 먼저 회수하며 중복 반환 구멍을 수정함.
- 타입·문자열 경로 표 대신 enum과 프리팹 참조의 PopupDef·UIComponentDef 자동 등록을 선택. 팝업 수명과 공용 연출을 기반 클래스로 올리고 자식의 base.OnOpen 호출은 없앰.

## UI 기반과 화면 점검

- 직접 반복 연출은 UISequence로, 생성·삭제는 ResourceManager로, 문구·희귀도는 StringDef·RarityDef로 모으게 함. 문구 키는 enum 순서에 영향받지 않게 이름 문자열을 쓰도록 결정함.
- UI 확장을 공용화하되 과도한 적용·매니저 null 검사는 되돌리고 DB 조회는 TryGet으로 통일. 앱 종료는 종료 플래그와 PlayerDataManager 자체 저장으로 정리함.
- Screen·Popup·Component·Helper와 UIReuseService 명명을 정리하고 지도·툴팁·목록·참조 오류를 수정. 직접 프리팹과 두 씬을 재생성해 공통 캔버스·SafeArea 구성을 확인했으며 컴파일 확인 기록을 남김.
- 확인 팝업은 결과만 알리고 게임 정지·해제는 호출한 쪽이 맡도록 지정. PC에 옛 사본이 전달되던 문제는 전송 방식 교정으로 대응함.

## Flow 설계와 에디터 도구

- 직접 GameManager의 씬 전환과 FlowManager의 진행 관리를 나누고, 공용·전용 Service 소유권과 씬 재로드 없는 다시 하기를 제안. AI가 상태·정리 입구 중복을 짚고 설계 문서로 정리함.
- 직접 채택한 에디터 정리를 AI가 반영해 역할별 폴더·명명·메뉴를 통일. 중복·일회성 메뉴를 없애고 원하는 UI만 다시 만드는 도구를 추가함.
- IReadOnlyList 지원 요청으로 컬렉션 기본값 조회를 보완. 일반 IEnumerable 경로는 해당 인덱스까지 순회함.

# 26.11.22 - 시장·정비·게임 흐름과 퍼펙트 닷지

## 주요 작업

- 시장 거래·화면 책임, 정비 능력치·패시브, Flow·로딩·다시 하기를 정리.
- 직접 전투 기준과 화면 방향을 정하고 AI에 구현·리소스 제작·리뷰 수정을 맡김.

## 시장 거래와 팝업

- 직접 시장 코드 정리를 지시. AI가 판정을 한곳으로 모으고 거래 결과로 가격을 전달하며 MarketChanged 한 번으로 화면을 갱신하도록 정리함.
- 신뢰도 저장은 MarketData, 판매가·방문 가중치·시장 상태는 HuntData로 분리. 읽기 어려운 PopupMarket은 선택 상태·상인 정보·시작 연출로 나누고 연출 수명은 PopupBase로 모음.
- 가격 누락과 희귀도 배율 오류를 수정하고 상인의 선호 범위·시세를 반영. 묶음 전체 선택·개수 조절·빈 재고·시장 떠나기 확인을 정리했으며 가격·수치는 가안으로 둠.
- 팝업 재개방 시 구독 중복과 이전 표시 잔존을 수정. 결과 칸 크기 문제는 검토 결과 실제 버그가 아니었음을 정정함.

## 정비·능력치·패시브

- 직접 골드 강화 5줄·연계/극의 노드·엠블렘 보너스를 정함. AI가 34개 노드와 5단계 엠블렘을 구현하고 일부 스페셜을 제안했으며, 장비·코스튬은 후속 범위로 둠.
- % 강화가 정수 반올림으로 사라지지 않도록 피해·체력·부위 내구도를 확대. 직접 지적으로 UnitStat을 출처별 StatFeature·StatModifier로 바꾸고 피해 계산은 DamageCalculator에 모음.
- 스페셜별 클래스가 늘어나는 안을 교정해 AI의 ‘언제 + 조건 + 효과’ 패시브 조합을 채택. 별도 보류했던 패시브 훅도 도입하고 상해보험은 즉시 골드 대신 동전 픽업을 떨구게 함.
- 지역 배율은 몬스터 에셋에서 MapDef 수정치로 옮겨 스폰 때 적용. 노드 저장·디버그 조작·결과 골드 표시를 추가했으며 비용 조정은 직접 판단할 몫으로 남김.

## 타이틀·로딩·UI 소유권

- 로딩을 별도 씬으로 둔 초안은 다음 씬을 읽는 동안 표시할 수 없어 거절. AI가 상시 오버레이와 최소 노출 시간을 구현하고 타이틀 클릭 연출 뒤 로비로 넘어가게 함.
- 클릭 연출은 기존 버섯 아이콘을 재사용하고 지정한 버튼에서만 재생하도록 결정. 직접 책임 혼재를 지적해 UIManager가 씬 UI 루트·OverlayLoading·클릭 연출을 맡고, 조각은 띄운 자리별로 회수하게 함.
- Screen·Popup·Overlay 분류와 OverlayBase를 채택. 대장이 컴파일 오류 없음을 확인했으며 로딩에 남던 클릭 조각의 회수 누락을 수정함.

## 게임 진행과 다시 하기

- 일시정지는 App·Focus·Confirm·Market 이유를 합산하도록 채택. AI가 GameManager의 씬 전환, FlowManager의 공용 서비스, 각 Flow의 전용 서비스를 분리하고 SceneDef로 씬을 연결함.
- 전투는 Start·Play·Down·Market·Result로 나누고 화면은 표시·요청만, Flow는 전환·팝업·보상을 연결하도록 정리. 사망·결과·시장 팝업은 Flow를 주입받는 공통 기반으로 묶음.
- 직접 새 인스턴스 생성도 피하라고 지적해 다시 하기는 같은 Flow·Service를 End → Begin으로 재사용. 맵·공용 UI는 유지하고 유닛·픽업·이펙트는 회수하며 FlowBegan으로 HUD·카메라를 다시 연결함.
- 맵 진입·다시 하기에는 클릭 시작 대기를 추가. 판단 정지·종료 버튼은 상태 변경 시 갱신하고 픽업은 BattleService에서 함께 갱신하며, 편집기 공식값 이름은 MonsterFormula로 정리함.

## 퍼펙트 닷지와 러시

- 직접 판정 기준을 무적 피격 즉시 발동에서 ‘공격 직전 범위에 있다가 대시로 피함’으로 변경. 돌진은 남은 경로와 통과 시점으로 판단하고, 스침 판정 대신 공격 범위를 넓히도록 정함.
- AI가 슬로우·반격 대상 접근·좌우 연타·막타와 상태 알림을 구현. 러시는 회피를 일으킨 공격자를 노리고, 전투 종료·풀 반환 때 정리하도록 연결함.
- 직접 ‘피하는 쪽의 일’이라고 지적해 판정 책임을 PerfectDodgeFeature로 이동. AttackAction은 공격 흐름과 알림을 맡고 판정·예고·회피 알림을 보조 클래스로 분리함.

## 리소스·화면 반영

- 직접 용도·방향을 정해 AI에 시장 슬롯·엠블렘·타이틀·HUD 그림과 러시 애니 3종 제작을 맡김. 최종 디자인과 직접 손본 화면 값을 생성기에 반영하고 글자 넘침·버튼 누름 영역을 수정함.

## 설정·절차·프로젝트 검토

- 직접 전역 조절값을 성격별 스펙과 Define 편집기로 나누고, 플레이어 대시·러시는 DashSpec·RushSpec으로 모으게 함. 에셋 값은 보존하며 하드코딩된 제한값도 데이터로 옮김.
- PR 리뷰에 따라 애니 이름 변경 절차를 ‘표 수정 → FBX 재임포트 → 애니메이터 재생성’으로 보완.
- 프로젝트 자료에서 읽기 쉬운 책임 분리·반복 작업 자동화·직접 판단의 가치를 AI가 추론. 해석의 사용자 채택은 별도로 확정하지 않음.
