# 26.11.18 - 데이터 도구·전투 구현과 아트 제작

## 주요 작업

- 데이터 편집기·몬스터/스폰 자동 배정 구현.
- 부위 파괴·공격/스킬·애니메이션 연결과 스폰 버그 수정.
- 지역·시장·HUD 아이콘 제작, 액터 실행 구조 공통화.

## 데이터 편집기·자동 배정

- 직접 타입별 표·연관 Def·모델 차이·빌드를 요구하고 필드 나열식 초안은 거절. AI가 UI Toolkit의 표 직접 편집+상세 영역으로 재구현, 기존 변경은 보존.
- 모델 등록·Def 삭제·버섯 모델별 제안·빌드를 연결. 임시 에셋으로 중복·값/GUID 보존·저장·Undo·삭제 후 재제안 확인, 실제 Def 삭제는 취소.
- 직접 맵-버섯-몬스터 연계와 순서 기반 공식을 요청. 밸런스는 MonsterBalance에서 조정하고 판정·히트스톱은 자동 배정 제외. 공유 HitDef 보호를 위해 넉백 자동 배정도 제거.
- 스폰 배치는 잡몹·엘리트·보스 규칙으로 자동화하고 기존 리스폰 유지. 미리보기만 확인, 적용은 직접 실행. 지역 버섯·밸런스 수치는 가안.

## 피격·부위 파괴·보스 조립

- 직접 피격 반응 통합을 지시하고 수치는 손으로 이전. AI가 HitFeature·공유 HitDef와 뼈 기반 몸 판정을 구현.
- 부위 종류·소켓을 정리하고 원본 뼈 참조를 프리팹으로 이동. 계획에만 완료로 적힌 부위 기능을 실제 구현한 뒤, 직접 보스 나무 기준·보스만 파괴로 범위 결정.
- 보스 3종의 부위·깨진 모델·드랍·공격 데이터를 연결. 부위당 파괴 칸 하나라 일부는 장식. 곰의 구름버섯 데이터는 수정, 당시 누락 판정·재굽기는 과제로 남김. 임시값이며 컴파일 또는 로드만 확인.
- 이후 직접 부위 단위 파괴·랜덤 버섯을 선택. PartEntry·UnitProperty로 개편하고 PartFeature를 유닛당 하나로 통합. 모델은 미리 생성해 재배치하고 잡몹 소켓 유실은 None 부위로 보존. 후반 개편은 컴파일·실행 안 함.
- 번쩍이 오류는 깨지지 않는 부위를 몸 피격으로 처리해 수정. 큰 공격의 부위 우선 판정은 남겼고, 당시 신선도는 획득 뒤 버려져 저장·표시되지 않았음.
- 통 메시 부위 번쩍은 포기하고 기존 피격 좌표·조각으로 도트 타격 마크 제작·강조. 플레이어 피격에도 표시되며 수치는 임시, 컴파일만 확인·플레이 미확인.

## 공격·스킬·애니메이션

- 직접 공격 구간·공용/개별 쿨 분리와 기본 공격의 SkillDef화를 결정. AI는 실행·데이터 구조를 정리했고, 애니 길이 조회에 맞춰 클립=상태 이름으로 통일.
- 직접 공격 6종을 지정하고 PC에 Blender가 없어 클라우드 출력 선택. AI가 플레이어 클립·보스 Hitbox 방향을 수정해 FBX 출력·미리보기 확인. 다른 FBX·팔레트는 보존, Unity 임포트·플레이 미확인.
- 새 클립이 없는 FBX 연결은 원복했다가 새 파일로 재연결. 승인 후 좌→우→막타 콤보·달리다 베기·위로 치기 구현, 판정 전 연타 무시·콤보 초기화 적용. 임시값, 컴파일·로드만 확인.
- 내려치기는 보류하고 길게 누르기 회오리 선택. 입력 지연을 피하려 즉시 콤보 후 회오리 연결, 좌우 전환은 블렌딩 추가. 두 바퀴째 미타격은 재타격 간격으로 수정. 컴파일만 확인.
- 보스 공격 불가는 캡슐 표면 기준 거리와 실제 클립으로 수정. 회전 속도·피격 색·몸 판정도 데이터화했으나 수치와 플레이 확인은 남음.

## 스폰·맵 버그 수정

- 직접 슬롯별 MonsterDef 직접 참조를 선택하고 런타임 Find·ID 간접 참조는 보류. 선택 맵은 씬 고정 대신 MapDef.Prefab에서 생성하도록 변경.
- 지면 보정만으로 해결되지 않던 낙하는 슬롯의 X 90도 회전이 원인. 스폰 yaw 제한 후 직접 지시해 FBX 가져오기 단계에서도 수정. 기존 가져오기 경고는 별개로 남음.
- 올라타기는 자동 계단 오르기로 확인해 접촉 시 stepOffset 0 적용·바닥 스냅 제거. 보스·곰·호랑이는 수동 Move로 해소 확인.
- 직접 레이어·맵 래핑·버퍼 없는 거리 비교를 선택. 지형으로 물리 쿼리 버퍼가 차는 문제를 피하고 사각형 검색은 이득 없어 보류. 구조 변경은 컴파일·플레이 미확인.

## 아이콘 제작

- **지역:** 직접 컨셉·스케치·수정 방향을 제시. AI가 평원/보스 나무·얼음·공룡/화산 3종을 스티커·디오라마로 제작. 캐릭터·소품·지역색 테두리를 보완하고 그림 64px+여백의 72px 캔버스로 정리. 초기 외형은 이름으로 추정, 임포트·MapDef 연결 안 함.
- **시장·HUD:** 직접 항목·크기·용도 지정. 버섯 5종·공통 썩음 덮개·변종 별, 조이스틱·공격·대시·밤 시계·종료 아이콘 제작. 모델 팔레트와 공용 덮개, 코드 색 적용·Radial360 방식 선택. 밤 시계·종료 아이콘은 연결·임포트 안 함.
- 생성 스크립트는 다른 결과물 덮어쓰기를 피하도록 분리. 자물쇠 등 추가 5종은 직접 판단 대기.

## 액터 실행 구조 공통화

- 직접 상속+Feature를 선택하고 ‘컨트롤러는 판단, Feature는 실행’으로 경계 설정. AI가 공격 선택·대시를 분리하고 공격 실행·Next 기반 콤보를 플레이어/몬스터 공용화.
- 유닛 Tick은 ActorService로 모으고 Despawn은 순회 후 처리. 씬 직접 배치는 미지원, 스폰은 Tick 밖에서만 처리하는 범위로 결정. 컴파일 안 함.

## 보조 도구·문서 정리

- **명명·이전:** 직접 3자리 번호·Mon/Mush/Map·DexNo 등을 확정. GUID·직렬화 값을 보존해 변경 후 일회성 이전 코드는 제거. 세이브는 직접 초기화를 선택했으며 버전 3 미만은 초기화 필요.
- **공용 도구·UI:** 사전/Inspector 추가, 샘플·메뉴·경로 정리. 사전의 미완성·중복 행 보존과 Undo·재로드 확인. 결과 UI는 템플릿을 그리드 밖으로 옮기도록 셋업 수정, 재생성은 직접 수행할 몫.
- **문서·환경:** 문서 형식·참고 링크·로그 경로 통일. 직접 graphify 삭제와 긴 스레드 정리·큰 파일 부분 읽기를 선택, AI가 연결·생성물·CLI 제거·실행 배치파일 작성. 토큰 원인 분석은 수치 근거 없는 추정.

# 26.11.19 - 공통 행동·이펙트 구조 정리와 제출 준비

## 주요 작업

- 공통 행동·AI·판정·부위 책임과 UnitController 구조 정리.
- 공격·부위 파괴·사망·줍기 이펙트 제작·서비스 통합.
- 제출 가치·마감 범위 평가, 라이선스·AI 협업 로그 정리.

## 액터 구조·책임 분리

- 직접 상태가 Feature를 감싸는 구조를 지적하고 AI도 Feature로, 컨트롤러는 허브로 선택. AI가 ActionFeature·공통 행동 5종·AIFeature·팀 기준 적 탐색 구현.
- 판단/행동 분리, 행동별 끊기 규칙·공격 안의 예고·종료 알림 순서로 중복과 콤보 충돌 개선. 병행 작업 중인 공격·피격 파일은 보존.
- 직접 판정/파괴 분리 채택. 몸 판정은 HitBoxFeature, 부위 번호·드롭·피격 연결은 PartFeature 담당. 신선도는 사망 상태로 판단하고 이동은 SetMove로 통일.
- ActorService가 HitBox를 직접 읽어 중계 접근 제거. EAIState·AI*State로 이름 통일, .meta GUID 유지.
- 인터페이스 필요성을 직접 지적해 비제네릭 UnitController 기반으로 변경, IActor·IHitTarget·getter 중복 제거. 제네릭은 Def만 보유하고 필드명 유지로 재굽기 불필요.
- 직접 Unit 쪽이 아직 혼란스럽다고 지적해 AI에 문제점·개선안 정리를 맡김. 판단을 양쪽 다 Feature로(B)·공통 반응을 기반에서(C)·층별 폴더(A) 중 B·C만 진행 선택.
- AI가 BrainFeature(전투 종료 시 스스로 멈춤·피격·사망·행동 끝 훅) 도입, 플레이어 입력은 PlayerInputFeature로, 몬스터 대상·스폰 자리·행동 뒤 판단은 AIFeature로 옮김. 컨트롤러는 SetFeatures·CreateBrain만 남기고 OnUpdate·OnHit·OnDied·OnBattleEnded 폐지, HitParams.Attacker를 UnitController로 바꿔 TryGetComponent 제거.
- 직접 통합 후보 중 팀·사망 여부·콤보 다음 타·대상(TargetFeature)·애니 이름(AnimKey)·AttackChoice 위치를 채택, 대시 수치는 스킬 통합 때로 보류. AI가 반영하고 Unit/Core·Data·Feature·Action·Brain 층별 폴더로 이동(.meta 함께, PC 스크립트).
- 직접 "판단=Feature, 행동=Action"만으로는 정리가 안 된다고 지적. AI가 Feature를 상태·능력·입구로 나눈 역할표를 만들고, 얇은 Feature 합치기 후보(HitBox→Hit 등)를 제안.
- 직접 Feature 계층(능력·상태·입구·층) 혼재가 가장 산만하다고 지적. AI가 부품·행동·판단 3층과 호출 방향 고정을 제안, 직접 Health 분리 유지와 한 덩어리씩(부품 → 행동 → 판단) 진행·단계마다 컴파일·커밋을 선택.
- AI가 HitBox→Hit, ActionFeature→ActionLayer·Melee→AttackAction, BrainFeature→BrainLayer(Player/MonsterBrain)·Target→TargetSensor·AttackChoice→MonsterBrain 안으로 반영. 직접 프로퍼티 이름을 ActionLayer로 바꿔 판단도 BrainLayer로 맞춤.
- 위 구조 변경은 3단계 컴파일 안 함(1·2단계는 직접 컴파일·커밋).
- 직접 "AI 상태가 MonsterBrain만 받으면 의미가 없다"고 지적. AI가 AIBrain 기반으로 상태를 몬스터 판단에서 떼는 안을 제안, 직접 채택(3단계는 직접 컴파일 확인).
- AI가 심사자 관점 점검에서 "쓰이지 않는 일반화"를 짚고 IAIDef 제거·두 번째 판단 추가를 제안. 직접 채택해 버더지 BurrowBrain(맞으면 땅속에 숨는 AIHideState를 SetState로 추가, MonsterDef.Brain으로 선택) 반영(컴파일 전).
- 직접 보스 상태(포효·부위 파괴 쓰러짐·분노)와 동료 판단 추가, 숨은 적 조준 제외를 지시. AI가 무적 전체를 빼면 피격 직후 무적 때문에 콤보 조준이 튀어서 숨기 전용 플래그(HitF.IsHidden)로 좁힘.
- 직접 "상속으로 판단을 쪼개니 지저분하고 Idle·Dead가 몬스터 전용인 이유가 없다"고 지적. AI가 원인을 MonsterDef에 섞인 AI 수치로 짚고, 판단 하나(AIBrain)+상태 하나(AIState)+종류별 상태 묶음(AISpec.Type)과 드롭의 DropFeature 분리를 제안, 직접 채택. AI 수치는 공유 SO 대신 MonsterDef 안 직렬화 클래스(AISpec)로 옮김(자동 배정이 몬스터별 값을 쓰기 때문). 몬스터 에셋 15개 YAML 이전·데이터 툴 경로 수정(컴파일 전).
- 직접 "AI Def로 일반화해 프리셋 재활용"을 지시. AI가 AISpec을 공유 SO AIDef(프리셋 Normal·Burrow·Elite·Boss·Pet 5개)로 바꾸고 UnitDef.AI로 참조, 이동 속도만 UnitDef.MoveSpeed로 몬스터별 유지. 몬스터 15개 에셋 프리셋 배정, 자동 배정은 MoveSpeed만 기록(컴파일 전).

## 드랍 버섯 희귀도 고리

- 희귀도를 필드에서 보여 주려고 AI에 맡김. 원판 → 큐브 파티클 → 바닥 빛 원·빛기둥 → 버섯 자체 발광·색 물들이기까지 여러 번 시도했으나 매번 안 보이거나 예쁘지 않았고, AI가 결과 에셋을 확인하지 않고 보고하거나 옛 파일을 PC에 보내는 실수가 겹침. 직접 판단으로 희귀도 연출을 전부 걷어냄(희귀도는 시장 UI 배지로만 보임). 드랍 버섯 1.2배 크기만 남김. 교훈: AI 산출물은 결과물까지 확인해야 함.
- 이후 빛기둥만 다시 넣게 함(새 컨트롤러 금지). 희귀도별 FX 프리팹(Rare 파랑·Epic 보라, 길이 3.6m)을 기존 EffectController로 만들고, MushroomPickup이 땅에 닿을 때 ResourceManager로 꺼내 붙이고 주울 때 돌려놓음. 프리팹·머티리얼 YAML은 AI가 직접 작성. 컴파일·플레이 확인 안 함.

## 공용 컬렉션 기본값 조회

- 직접 IReadOnlyList도 사용할 수 있는 범용 E_GetOrDefault 작성을 요청. AI가 기존 IList 오버로드는 유지하고 미완성 IEnumerable 오버로드를 LINQ로 완성해 null·음수 인덱스·범위 초과에는 지정 기본값을 반환하도록 수정함.
- IReadOnlyList와 LINQ 결과를 받을 수 있으며 일반 IEnumerable 경로는 해당 인덱스까지 순회함. 컴파일·테스트·Unity 실행은 수행하지 않았고 수정본의 직접 확인·채택은 미정.

## UI 목록 풀 구조 개편·UI 이름 정리

- 직접 구조(가공 데이터 리스트는 UI 소유 → `UIListPool.Refresh(list, onSet)` → 칸은 표시만, 클릭은 `IndexOf`)와 이름 규칙(`PopupMarket`, `HUDBattle_LootRow`처럼 첫 밑줄 제거)을 정함. AI가 `ResourceManager.Spawn(prefab, parent)`·`PoolableMonoUI`를 추가하고 시장·결과·전투 HUD 목록을 이 흐름으로 바꿈. 칸 반환은 팝업 `OnClose`와 씬 전환 직전 `SceneUnloading` 이벤트에서 함.
- 상인 줄·주운 버섯 줄은 열린 에디터에서 팝업·HUD 안 템플릿을 독립 Resources 프리팹으로 빼고, 칸은 기존 `UICommonSlot` 프리팹을 씀. 에디터 컴파일 오류는 없었으나 플레이 확인은 하지 않음.
- 직접 개편 뒤 칸·UI가 깨졌다고 알리고 일괄 재생성 메뉴와 안 쓰는 기능 삭제를 요청. AI가 공용 칸 프리팹의 값 글자(m_NameText) 미연결과 칸 위치 원복을 원인 후보로 보고, 원복은 크기·회전만 남김. `MushTaker/UI/모든 UI 다시 만들기` 하나로 공용 부품·팝업·HUD 프리팹을 같은 경로에 덮어써 다시 만들게 하고, 개별 시장·결과 팝업 메뉴, 슬롯 칸 갱신 메뉴, 옛 ResultScreen 프리팹을 지움. 메뉴 실행은 자동 권한 검사가 막아 대장 몫으로 남김.
- 직접 UI 스프라이트 폴더 정리를 요청. AI가 48장을 Common·HUD·Icon·BG로(대장 지시로 Icon 하위 폴더·Lobby 폴더는 없앰) .meta와 함께 옮기고(GUID 유지), 생성기가 폴더 대신 이름으로 찾게(`UIBuilder.LoadSprite`) 바꿈. 곰팡이 그림이 Cube 텍스처로 들어와 칸이 흰색이 된 문제는 2D로 고침.
- 직접 결과 팝업의 창·페이드 필드가 공용이어야 하지 않냐고 지적. AI가 여는 연출(페이드 + 창 튕김)을 Popup 기반으로 올리고(비우면 연출 없음, 이어지는 연출은 CoAfterOpen), 사망·결과·개수 조절 팝업 생성기에 연결함. 수치는 기존 결과 팝업 값 유지.
- 직접 자식이 base.OnOpen()을 부르는 방식을 거절. AI가 PopupService가 부르는 `Popup.Open()`(내용 훅 OnOpen → 공용 여는 연출)과 자식용 `protected virtual OnOpen()`을 나누고, 자식의 base 호출을 없앰.

## 팝업 경로 표·Popup 기반 정리

- 직접 팝업 프리팹을 HUD·시장 필드에 꽂지 말고 경로로 불러오되 경로는 UI Table로 정리하라고 정함. AI가 `UITable`(타입 → Resources 경로 표, `UITable.Load<T>()`)을 만들고 CommonPath의 UI 경로를 옮김. `PopupService.Open<T>()`가 표로 원본을 불러오게 하고 HUDBattle·PopupMarket의 팝업 프리팹 필드와 생성기 연결을 지움.
- 직접 타입 키 표를 거절하고 팝업별 enum을 ID로, 경로는 따로 기입하며 팝업과 일반 UI를 섞지 말라고 정함. AI가 `EPopupType`·`PopupTable`(ID → 경로)로 바꾸고 `PopupService.Open<T>(EPopupType)`로 열게 함. 칸·줄 경로는 CommonPath로 되돌리고, 키 충돌로 생겼던 체력바 프리팹 필드도 경로 로드로 바꿈. UITable.cs 삭제는 대장 몫.
- 직접 Popup 정리 3건 반영을 지시. AI가 OnOpen·OnClose를 둘 다 protected로 두고 서비스 진입은 `Open()`·`Dismiss(isInstant)`로 나눔. 여는 연출의 반대인 닫는 연출(페이드 아웃 + 창 축소)을 공용으로 붙이고 OnClose는 연출 뒤에 부름(씬 정리 땐 바로). 페이드 시간은 const. 컴파일·플레이 확인 안 함.

## UI 공용 요소 정리·목록 풀 이전

- 직접 UI 코드 정리·개편 후보 제시를 요청. AI가 UI 스크립트와 생성기를 읽고 정리(동작 그대로) 5건, UIListPool 이전 3건, 기능 개편 2건(슬롯 레이어 표·희귀도 표)을 제안함. 직접 정리·이전 8건만 진행하게 함.
- AI가 대장 메모 3건을 `E_SetActive`·`E_SetText`·`E_SetImage`(null이면 넘어감) 확장으로 처리하고 UI 전반에 적용. UICountLabel의 GetComponent를 직렬화 필드로 바꾸고 골드 ID는 `CurrencyDef.GoldID`를 씀.
- 비슷한 unscaled 연출 루프(팝업 열기·닫기, 툴팁, 결과 칸 튕김, 밤 시계)를 `UITween.CoPlay(duration, onUpdate)` 하나로, 결과 팝업 시간 표기를 `UINightClock.FormatRealTime`으로 합침. 버섯 칸 채우기는 `UICommonSlot.Set(itemID, def, count)`·`SetLoot(key, def, count, text)`로 모음. 시장 개장 연출 루프는 건너뛰기 조건이 있어 그대로 둠.
- 로비 버섯 칸(Instantiate/Destroy 반복), 전투 스킬 줄 아이콘(꺼 둔 템플릿)을 UIListPool로, 몬스터 머리 위 바(자체 Stack 풀)를 ResourceManager 풀로 옮김. 아이콘·머리 위 바는 독립 Resources 프리팹으로 빼고, 머리 위 바는 UIGauge라 UITable 키가 공용 게이지와 겹쳐 직렬화 필드로 둠.
- 팝업 정리 스레드와 같은 파일을 만져서, 겹치지 않는 파일을 먼저 쓰고 그쪽이 끝난 뒤 최신본 위에 얹음. 컴파일·플레이 확인 안 함.

## UI 요소 재활용 구조(UIFactory·UIListView)·팝업 재사용

- 직접 팝업 표처럼 팝업이 아닌 UI 요소에도 표와 재활용 구조가 필요하다고 지적하고 이름은 UIComponentTable·EUIComponentType으로 정함. AI가 enum 키 표를 만들어 같은 클래스(UIGauge)가 다른 프리팹을 쓰는 충돌도 풀고, CommonPath의 칸·줄 경로를 옮김.
- AI가 재활용을 `UIFactory`(ResourceManager를 감싸 꺼낸 요소를 기억, 씬 전환 때 일괄 회수)와 목록형 `UIListView`(옛 UIListPool)로 나누자고 제안, 직접 채택. 화면마다 있던 씬 전환 회수 코드를 지우고, UIFactory를 PopupService보다 먼저 등록해 팝업 안 칸을 먼저 회수하게 함.
- 직접 팝업은 씬이 바뀔 때만 지우자고 정함. AI가 닫으면 끄기만 하고 종류마다 인스턴스 하나를 다시 쓰게 하고, 다시 열 때 닫기 상태·시장 시계를 되돌림. 컴파일·플레이 확인 안 함.
- 직접 경로를 손으로 적는 표(PopupTable·UIComponentTable)는 런타임에 있을 이유가 없다고 지적, 에디터 자동 등록을 고름. AI가 `PopupDef`·`UIComponentDef`(enum → 프리팹 참조 SO, 공용 기반 `UIPrefabDef`)로 바꾸고, "모든 UI 다시 만들기"·"UI 프리팹 표 갱신" 메뉴가 enum 이름과 같은 프리팹을 찾아 채우게 함. 런타임 경로 문자열이 사라짐. 컴파일·플레이 확인 안 함.
- 직접 `(RectTransform)` 강제 변환과 Unity 객체에 바로 쓴 `?.`·널 검사 삼항을 싫다고 지적. AI가 UI·UI 생성기에서 형변환을 `as`(또는 `RectTransform` 속성) + null이면 건너뛰기로, 널 검사 삼항과 `?.`를 `E_Alive()?.` + `??`로 바꿈. 컴파일·플레이 확인 안 함.
- 직접 Popup 닫기 이름을 `BeginClose`·`EndClose`로 바꾸고(AI 제안), 팝업 파괴를 ResourceManager 삭제 요청으로 모으라고 지시. AI가 `ResourceManager.Delete`·`S_Delete`를 추가해 팝업 파괴와 풀 밖 인스턴스 삭제를 그쪽으로 옮김.
- 직접 목록 배치를 LayoutGroup 없이 직접 좌표 계산으로 하라고 지시. AI가 처음엔 배치 값 컴포넌트 `UIListLayout`을 따로 만들었으나, 직접 "UIListView가 알아서" 하도록 지적해 배치 옵션을 `UIListView` 직렬화 필드(화면이 `[SerializeField]`로 들고 `Init`으로 칸 종류 지정)로 옮김. `UIListView.Arrange`가 세로·가로·격자 좌표와 내용 크기를 계산하게 바꿈. 화면 7곳·UI 생성기의 LayoutGroup·ContentSizeFitter·LayoutElement를 지움. 스킬 연계 알파 비교는 `Mathf.Approximately`로. 컴파일·플레이 확인 안 함.
- 직접 머리 위 체력바를 매 프레임 "안 보인 유닛" 검사로 회수하던 것을 유닛 삭제 이벤트로 바꾸라고 지시. AI가 `UnitService.UnitRemoved`를 구독해 바를 돌려주고 잡고 있던 보스도 놓게 함. 컴파일·플레이 확인 안 함.
- 직접 남은 UI 정리 항목을 골라 지시. AI가 연출 공용 `UISequence`(Tween·Join·Wait·Call·WaitUntil, 다음 대기 지점까지 건너뛰기)를 만들어 팝업 여닫기·결과 칸 순차 등장·시장 인트로를 옮기고, 생성·삭제를 `ResourceManager.Create/Delete`로 모음. 전투·매니저의 Unity 객체 `?.`·널 삼항을 `E_Alive`로, DB 조회를 `GameDatabase.S_TryGet`으로 통일. UIListView는 바뀔 때만 다시 배치하고 인스펙터 배치 미리보기를 붙임. 직접 만든 `E_SetText`로 `.text` 대입을 통일하고 `E_SetTextWithActive`·`E_SetInteractable`을 추가. 컴파일·플레이 확인 안 함.
- UI 접근 통일 2차. 직접 고른 4가지를 AI가 UI 코드 전체에 적용: `SetActive`→`E_SetActive`, CanvasGroup 보이기/숨기기→`E_SetVisible`(누름만은 `E_SetBlocksRaycasts`), 버튼 연결→`E_SetOnClick`(중복 연결 방지), 색·그림 대입→`E_SetColor`·`E_SetImage`. 컴파일·플레이 확인 안 함.
- 직접 지적: 이미 null 검사했거나 바로 아래에서 직접 쓰는 대상에 확장을 억지로 부른 곳, 매니저 Instance null 검사. AI가 전체 런타임 코드에서 매니저 Instance의 `?.`·null 검사를 걷어 내고, 해당 UI 확장 호출을 직접 대입으로 되돌림. 컴파일·플레이 확인 안 함.
- 이어서 뒤로 가기 팝업 닫기 조건 오류, 결과 칸 DB 누락 표시를 고치고, 앱 종료 때 매니저 순서 문제를 null 검사 대신 종료 중 플래그(씬 정리 건너뛰기)와 PlayerDataManager 자체 저장으로 정리(방향은 직접 결정).
- GameDatabase.Get을 없애고 조회를 TryGet으로 통일(직접 제안). 설정 Def가 없으면 호출한 쪽이 에러 로그.
- EffectService 고정 연출을 `ECommonEffectType`(이름=프리팹 이름)으로 부르게 정리(이름은 직접 결정). 밖에서 프리팹을 꺼내 넣던 코드와 빛기둥 직접 로드를 없앰.

- 직접 UI 칸 회수 확인을 AI에 맡김(코드 확인만). AI가 씬 전환 때 회수 순서는 맞다고 보고, 이미 회수한 칸을 다시 돌려주면 풀에 두 번 쌓이는 구멍을 찾아 `UIFactory.Despawn`이 꺼내 준 목록에 있을 때만 돌려받게 고침. 아이콘 깨짐은 디스크 참조가 모두 정상이라 증상 확인 대기. 컴파일·플레이 확인 안 함.
- 직접 로비 아이콘이 모두 빠졌고 골드도 연결하라고 지시. AI가 로비 생성기가 탭·골드 아이콘을 색 칸으로만 만들던 것을 찾아 탭 그림(Tab_Gear·Hunt·Breed·Dispatch)과 골드 그림을 넣고, 탭 이름을 확정안(정비·토벌·개량·파견)으로 맞춤. `UICountLabel`이 재화 Def 아이콘으로 아이콘 칸을 채우게 함. 컴파일·플레이 확인 안 함.
- 직접 UI 폴더·이름(Component·Helper·Popup·Screen, UIReuseService·PopupBase·ScreenLobby_HuntView 등)을 정리하고, 화면을 Screen 프리팹으로 두고 SceneController가 `m_Screen`을 캐싱하는 구조를 정함. AI가 `ScreenBase`·`GetScreen<T>()`를 만들고, 로비 생성기를 ScreenLobby 프리팹 생성과 씬 재생성으로 나누고, HUDBattle→ScreenBattle·PopupMarket_Count→PopupMarketCounter 이름과 프리팹 폴더를 스크립트 폴더에 맞춤. 컴파일만 확인, 플레이 확인 안 함.
- 직접 Component·Helper 검토 10건을 채택(UIGauge는 유지)하고, 하드코딩 문구를 표로 모으자고 제안. 이름(StringDef·EStringKey)·화면 접두·UILabel 구조를 정하고, enum 순서 문제는 직접 "enum 이름 문자열을 키로" 방식을 제안해 채택. - 직접 `E_SetText(StringDef.S_Get(키))`를 키만 넘기는 확장으로 통일하라고 지시. AI가 `E_SetText(키)`·`E_SetText(키, args)`·`E_SetTextWithActive(키, isActive, args)`를 추가하고 화면 코드 10곳을 바꿈. 문자열을 합치거나 변수로 넘기는 곳은 그대로 둠. 컴파일만 확인.
