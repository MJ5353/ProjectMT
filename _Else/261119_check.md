## 3. 상세 정보 (논의 항목)

### 입력 방식

- 현재: `InputSystem.actions`(프로젝트 입력 에셋)에서 액션을 이름 문자열로 찾고 Player 맵을 켠다.
- 선택지: (a) 그대로 유지. (b) 입력 에셋에서 C# 클래스를 생성해 이름 문자열 없이 타입으로 접근. (c) `PlayerInput` 컴포넌트. (c)는 GetComponent·인스펙터 연결이 늘어 대장 규칙과 맞지 않는다.
- 모바일 조이스틱·버튼(On-Screen Stick/Button)은 어느 방식이든 같은 액션 바인딩으로 붙는다.

### 스폰 회전

- 현재: 맵 FBX의 SpawnSlot(빈 오브젝트)이 X 90도로 누워 있어 수평 방향만 뽑아 쓴다.
- 원인은 Blender(Z-up) → Unity(Y-up) 축 변환으로 보인다(확실하지 않음).
- 선택지: (a) 코드 보정 유지. (b) 모델 임포트의 Bake Axis Conversion을 켜거나 Blender 출력 때 변환 적용. 맵 3종 재출력·확인이 필요하다.

### 이동 deltaTime 상한

- 현재: `MaxDeltaTime` 1/20초. 프레임이 튈 때 캡슐이 벽을 뚫거나 크게 떨어지는 것을 막는다.
- 지장: 20fps 아래로 떨어지면 이동만 실제보다 느려지고 애니·AI 시간은 그대로 흘러 위치가 살짝 어긋난다.
- 선택지: (a) 유지. (b) 큰 deltaTime을 1/20초씩 나눠 여러 번 이동(substep).

### 리소스 경로·로드 정리

- 현재: `HitMaterials`가 `Resources.Load`를 직접 부르고, `EffectService`는 `Prefabs/Effect/` 경로를 따로 들고, `ChunkRenderer`는 `Camera.main`을 직접 찾는다.
- 선택지: 경로 상수를 한 파일에 모으고 `ResourceManager.Load<T>(path)`(캐시 포함)로 통일. 카메라는 `GameManager` 접근자 하나로 노출.

### 몹 길찾기

- 현재: NavMesh 사용 없음. 직선 추적이라 나무·바위에 걸린다.
- 선택지: (a) NavMesh(AI Navigation 패키지 설치됨, 맵 3종 굽기 필요). (b) 전방 장애물을 옆으로 비키는 간단한 회피. (c) 마감 뒤로 미룸.

### 카메라

- 현재: 각도 고정, 나무에 가려진다.
- 선택지: 보스전 거리·각도 조정, 카메라와 플레이어 사이 프랍 숨기기 또는 반투명.
