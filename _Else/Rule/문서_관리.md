# 문서 · AI 기록 관리

최종 수정: 26.11.19
적용: 작업 문서·README·기획서·AI 실험 로그를 작성하거나 정리할 때만 참고한다.

## 문서 위치

- 진행 추적: **Goals** 저장소.
- 지난 기록 보관: **Records** 저장소.
- **ProjectMT** 저장소: README, AI 실험 로그, 기획서 링크만 둔다. 이 규칙 문서 및 참고 문서는 작업 관리 문서 쪽에서 관리한다.

## 작업 문서 형식

- AI 실험 로그를 제외한 작업 문서는 `1. 다음 단위 작업 → 2. 전체 작업 TODO 및 진행상황 → 3. 상세 정보 → 4. 결정된 사안` 순서로 작성한다.
- 진행 상태와 미정을 구분하고, 기존 내용과 결정 날짜를 보존한다.
- 승인된 **전투 부위 파괴 계획서** 형식을 다른 작업 Markdown에도 적용한다.
- 이 ‘작업 규칙’ 문서 자체는 기능 완료율을 추적하지 않는다. 개별 기능 진행 상태는 해당 작업 문서에서 관리한다.

## AI 실험 로그

- 기록 파일은 **`_Else/AI_실험_로그.md` 한 개**만 사용한다.
- 표를 쓰지 않고 **날짜별 요약 → 주요 작업 → 작업별 결과·판단 목록**으로 작성한다. 위의 일반 작업 문서 네 구획은 적용하지 않는다.
- 같은 날짜·주제는 기존 항목을 갱신한다. 같은 결과물의 제작·수정은 한 주제로 합치고, 별개 작업·판단은 구분한다.
- **AI에게 맡긴 것 / 직접 한 것 / 채택·거절·보류 판단**이 드러나게 쓴다. 날짜·판단 변화와 이유는 보존하고, 분담이 불명확하면 추정하지 않는다.
- 핵심 작업은 결과·판단에 분량을 쓰고, 이름·경로·메뉴·문서 등 보조 작업은 작은 주제로 묶어 짧게 쓴다. 한 항목은 1~2문장으로, 반복 설명·중간 시도 나열·불필요한 수치와 파일명은 덜어낸다.
- 임시값·남은 한계·미확인 범위는 남긴다. 검증은 실제 수행한 범위만 적고, 기록 작성을 위해 추가 검증하지 않는다.

```markdown
# yy.mm.dd - 작업 요약

## 주요 작업

- 핵심 작업
- 보조 작업 묶음

## 작업명

- AI에 맡긴 일과 직접 정한 방향.
- 결과와 채택·거절·보류 판단. 임시값·미확인 범위.

## 보조 작업

- 이름·경로·메뉴·문서 정리 등을 묶어 핵심만 기록.
```
