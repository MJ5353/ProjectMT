# 문서 · AI 기록 관리

최종 수정: 26.11.23
적용: 작업 문서·README·기획서·AI 실험 로그를 작성하거나 정리할 때만 참고한다.

## 문서 위치

- 진행 추적: **Goals** 저장소.
- 지난 기록 보관: **Records** 저장소.
- **ProjectMT** 저장소: README, AI 실험 로그, 기획·설계 문서(`_Else/Plan`), 규칙 문서(`_Else/Rule`)만 둔다. 날짜별 점검·메모 문서는 두지 않는다.
- 루트 `CLAUDE.md`·`AGENTS.md`는 `_Else/Rule/작업_규칙.md`를 가리키기만 하고 본문을 복사하지 않는다.

## 작업 문서 형식

- Goals 작업 문서는 `목표 → 다음 작업 1개 → 진행 상황 → 결정 기록` 순서로 쓴다. 결정이 바뀌면 이전 결정을 남긴다.
- 저장소의 기획·설계 문서는 `상세 정보 → 결정된 사안 → 미정` 순서로 쓰고, 다음 작업·TODO 구획을 두지 않는다. 진행 상황은 Goals 문서로 연결한다.
- 진행 상태와 미정을 구분한다. 결정 기록은 설계·동작에 영향을 준 선택과 이유·날짜만 남기고, 본문 반복과 단순 적용 이력은 줄인다.

## AI 실험 로그

- 기록 파일은 **`_Else/AI_실험_로그.md` 한 개**만 사용한다.
- 표를 쓰지 않고 **날짜별 요약 → 주요 작업 → 작업별 결과·판단 목록**으로 작성한다. 위 작업 문서 형식은 적용하지 않는다.
- 같은 날짜·주제는 기존 항목을 갱신한다. 같은 결과물의 제작·수정은 한 주제로 합치고, 별개 작업·판단은 구분한다.
- **AI에게 맡긴 것 / 직접 한 것 / 채택·거절·보류 판단**을 구분한다. 중요한 방향 전환의 날짜·이유는 남기고, 분담이 불명확하면 추정하지 않는다.
- 핵심 작업은 결과·판단 중심으로 항목당 1~2문장. 번호뿐인 묶음·단계·검토 항목 대신 담당 기능으로 이름 붙이고, 보조 작업·중간 시도·불필요한 수치·파일명은 줄인다.
- AI에 지시한 리소스 제작과 UI 디자인은 목적·최종 결과만 짧게 기록한다. 시안별 개선·픽셀·색·좌표 이력은 생략하고, 큰 방향을 바꾼 채택·거절 이유만 남긴다.
- 검증 상태는 `작업_규칙.md` 3장을 따른다. 임시값과 실제로 파악된 오류·구현 제한은 남기고, 검증은 사용자에게 전달받았거나 AI가 수행해 확인한 결과만 적는다. 기록 작성을 위해 추가 검증하지 않는다.

```markdown
# yy.mm.dd - 작업 요약

## 주요 작업

- 핵심 작업
- 리소스·문서 정리

## 작업명

- AI에 맡긴 일과 직접 정한 방향.
- 결과와 채택·거절·보류 판단. 임시값·구체적인 구현 제한.

## 보조 작업

- 이름·경로·메뉴·문서 정리 등을 묶어 핵심만 기록.
```
